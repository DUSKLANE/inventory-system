# 用户流程优化设计文档

日期：2026-08-02
状态：已批准（用户确认方案 A 与全部三段设计）

## 背景与目标

系统功能面广，但核心用户流程存在结构性问题（用户全选确认）：

- **入库入口混乱**：`/stock-in`（单件流程）与 `/scan`（批量扫码 + LCEDA 查料）两条平行路径；仪表盘"快速入库"指向能力更弱的 `/stock-in`；侧边栏同时有 入库/出库/扫描识别 三项
- **新器件入库是死胡同**：单件流程扫到不存在的编码只提示"请先新增器件"，需跳转 `/parts` 新建后返回重扫
- **出库只能单件**：除 BOM 领料外无批量出库入口
- **扫描页缺出库能力**：scan 页只支持入库，同一扫码设备不能用于出库
- **仪表盘数据不刷新**：仅挂载时拉取，操作后返回永远是旧数据
- **仪表盘不可操作**：统计卡/预警/最近记录不可点击
- **器件列表页**：无法自定义每页数量、无法直接跳转指定页、缺少编码/名称复制功能

**使用环境**：桌面为主、手机扫码、个人自用。不引入新依赖；不重构认证、Redis 适配器、图表页、深色模式体系。

**目标**：出入库合并为单一"收银台"式页面；仪表盘变为可操作、可刷新的实时入口；器件列表补齐每页数量、页码跳转、复制能力；补上缺失的流水展示页面。

## 设计决策

### 1. 统一「出入库」页 `/stock`

#### 1.1 新路由与页面结构

- 新路由 `/stock`（客户端组件 + Suspense 包裹，因使用 `useSearchParams`）
- 以 scan 页现有"待操作列表"模型为核心，整体搬迁并升级：
  - **模式 Tab**：页面顶部 入库/出库（URL 参数 `mode`，默认 `IN`）。模式影响：未知编码的处理、提交端点、配色
  - **待操作列表**：扫到/查到的器件加入列表（卡片），支持修改数量、入库模式可修改位置及新建器件信息（名称/封装/分类）、移除条目
  - **localStorage 持久化**：沿用 scan 页机制，存储键改为 `stock_pending_items`；**迁移兼容**：挂载时若旧键 `scan_pending_items` 存在且新键为空，读取旧键数据并写入新键
  - **添加方式**：扫码（复用 QRScanner）、手动输入编码、搜索已有器件加入
  - **去重逻辑**：沿用现有规则——1 秒窗口内同码忽略，超窗口累加数量
- 出库模式不允许添加未知编码（无器件可扣），提示且阻止

#### 1.2 提交端点（全部复用现有 API，零新增）

| 模式 | 端点 | 说明 |
|---|---|---|
| 入库 | `POST /api/parts/batch` `{action:"stock-in-upsert", items, reason}` | 未知编码自动创建并入库（现有） |
| 出库 | `POST /api/parts/batch` `{action:"movement", type:"OUT", items, reason}` | 逐项校验，库存不足该条失败（现有 `batchMovement` 语义） |

- 提交前预检：出库时库存不足的条目标红、默认不勾选；用户可剔除后提交剩余（服务端兜底防超卖）
- 提交后展示结果汇总（成功/失败数），可继续或清空列表

#### 1.3 入口统一

- 仪表盘/常用器件/收藏的"入库/出库"按钮统一指向 `/stock?code=X&mode=IN|OUT`，打开即自动加入列表并选中对应模式
- 库存预警条目 → `/stock?code=X&mode=IN`（见 §2）

#### 1.4 旧路由退役

- `/stock-in`、`/stock-out`、`/scan` 三个路由改为 `redirect()` 到 `/stock`（保留 `code`/`mode` 参数）
- 删除 `src/components/StockMovement.tsx`；仅被其使用的代码一并清理

#### 1.5 导航与快捷键

- 侧边栏 入库/出库/扫描识别 三项合并为「出入库」（/stock）；移动端底栏 入库/出库 两 tab 合并为一个「出入库」tab（腾出的位置保持 更多 菜单逻辑不变）
- 快捷键：`g i` → `/stock?mode=IN`，`g o` → `/stock?mode=OUT`，`g s` → `/stock`；帮助页快捷键表同步

### 2. 仪表盘「可操作 + 实时」与新增流水页

#### 2.1 数据刷新

- 挂载后 + `window` `focus` 事件触发时自动重新拉取（回到标签页即更新）
- 页面右上角加手动「刷新」按钮
- 不做定时轮询（个人使用，避免无谓的 Redis 压力）

#### 2.2 统计卡可点击

| 卡片 | 目标 |
|---|---|
| 器件总数 | `/parts` |
| 低库存预警 | `/parts?lowStock=true`（URL 参数已存在） |
| 今日入库 | `/movements?type=IN`（新流水页） |
| 今日出库 | `/movements?type=OUT`（新流水页） |

#### 2.3 库存预警条目直达入库

- 整行点击 → `/stock?code=X&mode=IN`（打开出入库页并自动带出该器件）
- 右侧小图标链接 → `/parts/[id]` 器件详情

#### 2.4 最近操作记录

- 修复 bug：「查看全部」当前错误指向 `/parts`，改为指向新流水页 `/movements`
- 记录行点击 → `/parts/[id]`（保留现状）

#### 2.5 新增「流水记录」页 `/movements`

- 背景：出入库流水（stock_movements）只有 API（`GET /api/movements`，已支持 `type`/`partId`/分页），无任何展示页面；操作日志页（/logs）记录实体操作（创建/更新/删除/BOM 领料），不含出入库流水
- 新页：分页列表 + 筛选（全部/入库/出库，按器件搜索），行点击 → 器件详情；复用 `/api/movements` GET；挂载时从 URL 参数 `type` 初始化筛选器（支持 `?type=IN|OUT` 直达）
- 导航加入口（侧边栏 + 移动端更多菜单）；快捷键 `g m` → `/movements`；帮助页同步
- `/logs` 操作日志页保持不变

### 3. 器件列表页增强

- **每页数量下拉**：分页栏加选择器（10/20/50/100），切换即刷新、页码重置为 1、写回 URL `pageSize` 参数（现有状态已支持 URL 同步）
- **页码跳转**：分页栏「第 X / Y 页」旁加输入框「跳至 [ ] 页」，回车跳转并写回 URL `page` 参数
- **复制功能**：桌面表格行 + 移动卡片的编码、名称旁各加复制小图标，点击 `navigator.clipboard.writeText` + toast「已复制」；hover 显示避免视觉噪音
